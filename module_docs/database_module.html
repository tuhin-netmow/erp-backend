📌 GET ALL TABLES

GET /api/database/tables

Endpoint Details

Method: GET

URL: /api/database/tables

Authentication: Protected (verifyToken)

Description: Retrieves a list of all tables in the database

Database Query

Uses Sequelize query interface
sequelize.getQueryInterface().showAllTables()

Response Example

{ "status": true, "message": "Tables retrieved successfully", "data": [ "users", "roles", "products", "customers", "sales", "purchases", "accounts", "attendance", "checkins", "settings" ] }
ℹ️ Note Returns all table names in the current database schema. Useful for database exploration and administration.
📌 GET TABLE DATA

GET /api/database/tables/:tableName

Endpoint Details

Method: GET

URL: /api/database/tables/:tableName

Authentication: Protected (verifyToken)

Description: Retrieves paginated data from a specific table

URL Parameters

Parameter Type Required Description
tableName string Yes Name of the table to query

Query Parameters

Parameter Type Required Default Description
page number No 1 Page number for pagination
limit number No 10 Number of records per page

Request Example

GET /api/database/tables/products?page=1&limit=20

Response Example

{ "status": true, "message": "Table data retrieved successfully", "data": { "data": [ { "id": 1, "name": "Product A", "price": 100.00, "status": "active", "created_at": "2026-01-01T10:00:00.000Z" } ], "pagination": { "total": 150, "page": 1, "limit": 20, "totalPage": 8 } } }
⚠️ Warning This endpoint executes raw SQL queries. Ensure proper access controls are in place to prevent unauthorized data access.
📌 UPDATE TABLE ROW

PUT /api/database/tables/:tableName

Endpoint Details

Method: PUT

URL: /api/database/tables/:tableName

Authentication: Protected (verifyToken)

Description: Updates a specific record in a table by ID

URL Parameters

Parameter Type Required Description
tableName string Yes Name of the table

Body Parameters

Parameter Type Required Description
id number Yes Record ID to update
...fields any Yes Fields to update (dynamic based on table)

Request Example

PUT /api/database/tables/products { "id": 1, "name": "Updated Product Name", "price": 150.00, "status": "active" }

Response Example

{ "status": true, "message": "Record updated successfully", "data": [ { "id": 1, "name": "Updated Product Name", "price": 150.00, "status": "active", "updated_at": "2026-03-11T10:30:00.000Z" } ] }

Side Effects

  • Updates the specified record in the database table
  • Automatically updates updated_at timestamp if the column exists
  • Returns the complete updated record
⚠️ Critical Warning This endpoint performs dynamic table updates. Should be restricted to admin users only. Ensure proper validation before use in production.
📌 DELETE ALL DATA

GET /api/database/delete-all-data

Endpoint Details

Method: GET

URL: /api/database/delete-all-data

Authentication: Protected (verifyToken)

Description: Truncates all tables and reseeds essential data

Process Flow

flowchart TD
    A[Start Delete All Data] --> B[Disable Foreign Key Checks]
    B --> C[Get All Tables]
    C --> D{Table in Skip List?}
    D -->|Yes| E[Skip Table]
    D -->|No| F[TRUNCATE Table]
    F --> G{More Tables?}
    E --> G
    G -->|Yes| D
    G -->|No| H[Enable Foreign Key Checks]
    H --> I[Seed Chart of Accounts]
    I --> J[Create Admin Role]
    J --> K[Create Superadmin Role]
    K --> L[Create Admin User]
    L --> M[Return Success Response]

Tables Skipped (Not Truncated)

SequelizeMeta Sequelize migration tracking
migrations Migration history

Data Seeded After Truncate

  • Chart of Accounts: Default accounting accounts
  • Admin Role: Full system access role
  • Superadmin Role: Full system access role
  • Admin User: Email: admin@erp.com, Password: password

Response Example

{ "status": true, "message": "All data deleted and accounting essentials seeded successfully" }
⚠️ DANGER: Irreversible Operation This will delete ALL data in the database except Sequelize system tables. This action cannot be undone. Use with extreme caution.
📌 RESET SYSTEM (PRESERVE FOUNDATION)

GET /api/database/reset-system

Endpoint Details

Method: GET

URL: /api/database/reset-system

Authentication: Public

Description: Resets transactional data while preserving foundational accounts, users, and settings

Process Flow

flowchart TD
    A[Start System Reset] --> B[Disable Foreign Key Checks]
    B --> C[Get All Tables]
    C --> D{Table in Keep List?}
    D -->|Yes| E[Preserve Table]
    D -->|No| F[TRUNCATE Table]
    F --> G{More Tables?}
    E --> G
    G -->|Yes| D
    G -->|No| H[Enable Foreign Key Checks]
    H --> I[Seed Chart of Accounts]
    I --> J[Ensure Superadmin Role]
    J --> K[Ensure Role Settings]
    K --> L[Ensure Admin User]
    L --> M[Return Response with Stats]

Tables Preserved (Not Truncated)

SequelizeMeta Migration tracking
migrations Migration history
accounts Chart of Accounts
users System users
roles System roles
role_settings Role configurations
role_menus Menu permissions
role_dashboards Dashboard access
settingss System settings

Response Example

{ "status": true, "message": "Database reset successfully. Foundational data preserved, transactional data cleared.", "data": { "total_tables": 45, "truncated_count": 36, "truncated_tables": [ "sales", "products", "customers", "purchases", ... ] } }
✓ Ideal For Development environment reset, clearing transactional data while keeping users, roles, accounts, and settings intact.
ℹ️ Note Default admin credentials: admin@gmail.com / password123
📌 RESET KEEPING ACCOUNTS ONLY

GET /api/database/reset-keep-accounts

Endpoint Details

Method: GET

URL: /api/database/reset-keep-accounts

Authentication: Public

Description: Resets everything except the chart of accounts and system tables

Process Flow

flowchart TD
    A[Start Reset Keep Accounts] --> B[Disable Foreign Key Checks]
    B --> C[Get All Tables]
    C --> D{Table in Keep List?}
    D -->|Yes| E[Preserve Table]
    D -->|No| F[TRUNCATE Table]
    F --> G{More Tables?}
    E --> G
    G -->|Yes| D
    G -->|No| H[Enable Foreign Key Checks]
    H --> I[Seed Superadmin Role]
    I --> J[Seed Admin Role]
    J --> K[Seed Role Settings]
    K --> L[Seed Admin User]
    L --> M[Count Accounts]
    M --> N[Return Response]

Tables Preserved

SequelizeMeta Migration tracking
migrations Migration history
accounts Chart of Accounts
users System users
roles System roles
role_settings Role configurations
role_menus Menu permissions
role_dashboards Dashboard access
settingss System settings

Data Reseeded

  • Superadmin Role: Full system access with wildcard permissions
  • Admin Role: Full system access with wildcard permissions
  • Role Settings: Default configuration for both roles
  • Admin User: Email: admin@gmail.com, Password: password123

Response Example

{ "status": true, "message": "Database reset successfully. Chart of Accounts preserved, all other data cleared.", "data": { "total_tables": 45, "truncated_count": 36, "truncated_tables": [ "sales", "products", "customers" ], "accounts_preserved": 50 } }
✓ Use Case Perfect for resetting the system while preserving the Chart of Accounts structure. All transactional data, users, and roles are reseeded to defaults.
⚠️ Important Even though 'users' and 'roles' tables are preserved, new admin user and roles are seeded using findOrCreate. Existing data in these tables remains intact.

⚠️ SAFETY & SECURITY CONSIDERATIONS

Important Warnings

🔒 Production Access Control These endpoints should be restricted to administrator users only in production environments. Consider implementing additional role-based access control (RBAC) checks.
💾 Backup Before Reset Always create a database backup before running any reset operations. Use the reset endpoints in development/testing environments only.
🚫 Public Endpoint Risk The reset-system and reset-keep-accounts endpoints are currently public. For production, these should be protected with verifyToken middleware and admin role verification.
🔍 SQL Injection Protection While dynamic queries use parameterized values, consider whitelisting allowed tables for additional security.
✓ Best Practice Implement audit logging for all database management operations to track who performed reset actions and when.
