The repository builds dynamic WHERE clauses based on filters:

async findAll(filters = {}, limit = 10, offset = 0) { const where = {}; // Status filter if (filters.status) { where.status = filters.status; } // Search across name and description if (filters.search) { where[Op.or] = [ { name: { [Op.like]: `%${filters.search}%` } }, { description: { [Op.like]: `%${filters.search}%` } } ]; } const { count, rows } = await Department.findAndCountAll({ where, limit, offset, order: [['created_at', 'DESC']] }); return { data: rows, total: count }; }

📌 SIDE EFFECTS & WARNINGS

Operations Impact

Creating a Department

  • ✓ Creates new DEPARTMENTS record
  • ✓ Validates department name uniqueness across all departments
  • ✓ Sets created_by to current user ID
  • ✓ Auto-generates created_at timestamp
  • ✅ Available for staff assignment immediately

Updating a Department

  • ✓ Updates specified fields only (partial update supported)
  • ✓ Validates name uniqueness if name is being changed
  • ⚠️ No updated_at field (timestamps disabled in model)
  • ✅ May affect staff assigned to this department

Deleting a Department

  • ⚠️ Permanently removes department record
  • ⚠️ Cannot be undone (no soft delete)
  • ⚠️ May fail if foreign key constraints exist
  • ✅ Consider using status='inactive' instead of deleting
⚠️ Important Warnings:
  • Department name must be unique - duplicates are rejected
  • Foreign key constraints from staffs.department_id may prevent deletion
  • No updated_at tracking - cannot see when department was last modified
  • No soft delete - deletion is permanent
  • Use status field for deactivation instead of deletion when possible
