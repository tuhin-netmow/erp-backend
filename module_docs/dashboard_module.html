📌 DASHBOARD STATISTICS

GET /api/dashboard

Retrieves aggregated statistics for the main dashboard including orders, customers, inventory, revenue, and staff metrics.

📊 Request Flow

flowchart TD A[Client Request] --> B[verifyToken Middleware] B --> C[Dashboard Controller] C --> D[Promise.all Parallel Queries] D --> E1[Order.count] D --> E2[Order.count - Pending] D --> E3[Customer.count - Active] D --> E4[Product.count - Low Stock] D --> E5[Order.sum - Revenue] D --> E6[Staff.count - Active] E1 --> F[Aggregate Results] E2 --> F E3 --> F E4 --> F E5 --> F E6 --> F F --> G[JSON Response]

⚙️ Controller Logic

📄 src/modules/dashboard/dashboard.controller.js
const getDashboardStats = async (req, res) => { try { // Execute 6 queries in parallel for optimal performance const [totalOrders, pendingOrders, activeCustomers, lowStockProducts, revenueResult, activeStaff] = await Promise.all([ // Total orders count Order.count(), // Pending orders count Order.count({ where: { status: 'pending' } }), // Active customers count Customer.count({ where: { is_active: true } }), // Low stock products (quantity <= min_stock_level) Product.count({ where: { stock_quantity: { [Op.lte]: sequelize.col('min_stock_level') } } }), // Total revenue from paid orders Order.sum('total_amount', { where: { payment_status: 'paid' } }), // Active staff count Staff.count({ where: { status: 'active' } }) ]); // Handle null revenue (no orders yet) const revenue = revenueResult || 0; // Return success response with all statistics res.json({ success: true, data: { totalOrders, pendingOrders, activeCustomers, lowStock: lowStockProducts, revenue, activeStaff } }); } catch (error) { res.status(500).json({ success: false, message: 'Error fetching dashboard statistics', error: error.message }); } };

🔨 Service Logic

Service Implementation:

The Dashboard module does not have a separate service layer. All business logic is implemented directly in the controller using Sequelize ORM methods.

Key Features:
• Uses Promise.all for parallel query execution
• All 6 queries execute simultaneously, not sequentially
• Reduces total response time significantly
• Handles null results gracefully (e.g., revenue with no orders)
• Uses Sequelize operators for complex queries (Op.lte for low stock)

💾 Repository Logic (SQL Queries)

📄 SQL Queries
-- Query 1: Total Orders SELECT COUNT(*) as totalOrders FROM orders; -- Query 2: Pending Orders SELECT COUNT(*) as pendingOrders FROM orders WHERE status = 'pending'; -- Query 3: Active Customers SELECT COUNT(*) as activeCustomers FROM customers WHERE is_active = true; -- Query 4: Low Stock Products SELECT COUNT(*) as lowStock FROM products WHERE stock_quantity <= min_stock_level; -- Query 5: Total Revenue SELECT COALESCE(SUM(total_amount), 0) as revenue FROM orders WHERE payment_status = 'paid'; -- Query 6: Active Staff SELECT COUNT(*) as activeStaff FROM users WHERE role = 'staff' AND status = 'active';

⚙️ Controller Logic

📄 src/modules/dashboard/dashboard.controller.js
const getChartsData = async (req, res) => { try { const currentYear = new Date().getFullYear(); // Get orders grouped by month for current year const monthlySales = await Order.findAll({ attributes: [ [sequelize.fn('MONTH', sequelize.col('created_at')), 'month'], [sequelize.fn('SUM', sequelize.col('total_amount')), 'total'] ], where: sequelize.where( sequelize.fn('YEAR', sequelize.col('created_at')), currentYear ), group: [sequelize.fn('MONTH', sequelize.col('created_at'))], raw: true }); // Month names mapping const monthNames = ['Jan', 'Feb', 'Mar', 'Apr', 'May', 'Jun', 'Jul', 'Aug', 'Sep', 'Oct', 'Nov', 'Dec']; // Create result with all 12 months const result = monthNames.map((name, index) => { const monthData = monthlySales.find(m => parseInt(m.month) === index + 1); return { name: name, total: monthData ? parseFloat(monthData.total) : 0 }; }); res.json(result); } catch (error) { res.status(500).json({ success: false, message: 'Error fetching charts data', error: error.message }); } };

🔨 Service Logic

Service Implementation:

The charts endpoint directly queries the database using Sequelize aggregation functions. No separate service layer exists.

Key Features:
• Uses SQL MONTH() and YEAR() functions for grouping
• Returns all 12 months even if no data exists (fills with 0)
• Guarantees consistent response format for chart libraries
• Uses raw: true for faster query execution
• Automatically filters for current year

💾 Repository Logic (SQL Queries)

📄 SQL Query
-- Query monthly sales for current year SELECT MONTH(created_at) as month, SUM(total_amount) as total FROM orders WHERE YEAR(created_at) = 2025 GROUP BY MONTH(created_at) ORDER BY month;

const getStaffsChartsData = async (req, res) => { try { // Use staff_id from query or fall back to authenticated user's ID const staffId = req.query.staff_id || req.user.id; const currentYear = new Date().getFullYear(); // Get orders grouped by month for specific staff const monthlySales = await Order.findAll({ attributes: [ [sequelize.fn('MONTH', sequelize.col('created_at')), 'month'], [sequelize.fn('SUM', sequelize.col('total_amount')), 'total'] ], where: { [Op.and]: [ sequelize.where( sequelize.fn('YEAR', sequelize.col('created_at')), currentYear ), { created_by: staffId } ] }, group: [sequelize.fn('MONTH', sequelize.col('created_at'))], raw: true }); // Month names mapping const monthNames = ['Jan', 'Feb', 'Mar', 'Apr', 'May', 'Jun', 'Jul', 'Aug', 'Sep', 'Oct', 'Nov', 'Dec']; // Create result with all 12 months const result = monthNames.map((name, index) => { const monthData = monthlySales.find(m => parseInt(m.month) === index + 1); return { name: name, total: monthData ? parseFloat(monthData.total) : 0 }; }); res.json(result); } catch (error) { res.status(500).json({ success: false, message: 'Error fetching staff charts data', error: error.message }); } };

🔨 Service Logic

Service Implementation:

The staff charts endpoint extends the general charts functionality with staff-specific filtering. No separate service layer exists.

Key Features:
• Automatically uses authenticated staff's ID if no staff_id provided
• Allows admins to query any staff's data by passing staff_id

• Returns all 12 months for complete year view

📌 PERFORMANCE & OPTIMIZATION

Performance Considerations

Current Implementation

AspectImplementationPerformance Impact
Query ExecutionPromise.all for parallel queries✅ Optimal - 6 queries run simultaneously
Data FreshnessReal-time (no caching)⚠️ May cause load with high traffic
AggregationDatabase-level (COUNT, SUM)✅ Efficient for moderate data sizes
Chart DataAll 12 months returned✅ Consistent response format

Recommended Optimizations

🚀 Performance Improvements:

1. Implement Caching:
• Cache dashboard stats for 5-15 minutes using Redis
• Reduces database load significantly
• Still provides near real-time data

2. Database Indexing:
• Add indexes on: orders(status), orders(payment_status), customers(is_active)
• Add composite index on orders(created_at) for chart queries
• Improves query performance by 10-100x

3. Materialized Views:
• Create materialized views for complex aggregations
• Refresh on schedule (e.g., every 15 minutes)
• Best for historical data analysis

4. Pagination for Large Datasets:
• If orders table grows large, consider pagination
• Use LIMIT and OFFSET for large result sets
• Implement cursor-based pagination for better performance

5. Background Jobs:
• Calculate stats in background jobs
• Store pre-calculated results
• Serve from cache for instant responses
