📌 LIST STAFF CHECK-INS (GET)

GET /api/staff-attendance

Retrieves all staff check-ins with filters for staff, customer, date, and search functionality.

📊 Request Flow

flowchart TD A[Client Request] --> B[verifyToken Middleware] B --> C[CheckInController.getCheckIns] C --> D[Parse Query Parameters] D --> E[page, limit, staff_id, customer_id, date, search] E --> F[CheckInService.getAllCheckIns] F --> G[CheckInRepository.findAll] G --> H[Build WHERE Clause] H --> I[Apply Filters] I --> J1[staff_id filter] I --> J2[customer_id filter] I --> J3[date range filter] I --> J4[search across staff/customer names] J1 --> K[StaffCheckIn.findAndCountAll] J2 --> K J3 --> K J4 --> K K --> L[Include Staff & Customer] L --> M[Order by check_in_time DESC] M --> N[Apply Pagination] N --> O[Return Results] O --> P[successWithPagination Response]

📝 Request Headers

HeaderValueRequiredDescription
AuthorizationBearer <token>YesJWT authentication token
Content-Typeapplication/jsonNoResponse content type

🔧 Validation Rules

ParameterTypeRequiredValidation
pagenumberNoInteger >= 1, default: 1
limitnumberNoInteger >= 1, default: 10
staff_idnumberNoValid staff ID from users table
customer_idnumberNoValid customer ID from customers table
datestringNoYYYY-MM-DD format
searchstringNoSearches staff names and customer/company names

⚙️ Controller Logic

// File: src/modules/attendance/checkin.controller.js async getCheckIns(req, res) { try { // Parse pagination parameters const page = parseInt(req.query.page) || 1; const limit = parseInt(req.query.limit) || 10; // Build filter object from query parameters const filters = { staff_id: req.query.staff_id, customer_id: req.query.customer_id, date: req.query.date, search: req.query.search }; // Call service layer with filters and pagination const result = await CheckInService.getAllCheckIns(filters, page, limit); // Return paginated response return successWithPagination(res, 'Check-ins retrieved successfully', result.data, { total: result.total, page, limit }); } catch (err) { return error(res, err.message, 500); } }

🔨 Service Logic

// File: src/modules/attendance/checkin.service.js async getAllCheckIns(filters = {}, page = 1, limit = 10) { // Calculate offset for pagination const offset = (page - 1) * limit; // Call repository with filters and pagination const result = await CheckInRepository.findAll(filters, limit, offset); // Return data and total count return { data: result.rows, total: result.count }; }

💾 Repository Logic (SQL Queries)

// File: src/modules/attendance/checkin.repository.js async findAll(filters = {}, limit = 10, offset = 0) { // Build WHERE clause based on filters const where = {}; // Filter by staff_id if (filters.staff_id) where.staff_id = filters.staff_id; // Filter by customer_id if (filters.customer_id) where.customer_id = filters.customer_id; // Filter by date (range query for full day) if (filters.date) { const startOfDay = new Date(filters.date); startOfDay.setHours(0, 0, 0, 0); const endOfDay = new Date(filters.date); endOfDay.setHours(23, 59, 59, 999); where.check_in_time = { [Op.between]: [startOfDay, endOfDay] }; } // Search across staff and customer names if (filters.search) { where[Op.or] = [ { '$staff.first_name$': { [Op.like]: `%${filters.search}%` } }, { '$staff.last_name$': { [Op.like]: `%${filters.search}%` } }, { '$staff.name$': { [Op.like]: `%${filters.search}%` } }, { '$customer.name$': { [Op.like]: `%${filters.search}%` } }, { '$customer.company$': { [Op.like]: `%${filters.search}%` } } ]; } // Execute query with includes and pagination return await StaffCheckIn.findAndCountAll({ where, include: [ { model: Staff, as: 'staff', attributes: ['id', 'name', 'first_name', 'last_name', 'email', 'phone', 'position', 'thumb_url'] }, { model: Customer, as: 'customer', attributes: ['id', 'name', 'company', 'email', 'phone', 'address', 'city'] } ], order: [['check_in_time', 'DESC']], limit, offset }); }

📌 SIDE EFFECTS

Operations Impact

Creating a Check-in

  • ✓ Creates new STAFF_CHECKINS record
  • ✓ Validates customer and staff existence
  • ✓ Stores GPS coordinates for location tracking
  • ✓ Calculates distance from customer location
  • ✓ Auto-generates created_at and updated_at timestamps
  • ✅ Available for sales activity reports
  • ✅ Tracks customer visits for performance metrics

Updating a Check-in

  • ✓ Updates specified fields only
  • ✓ Allows modification of notes and GPS data
  • ✅ Does NOT modify customer or staff references
  • ✅ Does NOT change check_in_time
  • ✅ Updates updated_at timestamp automatically

Deleting a Check-in

  • ⚠️ Permanently removes check-in record
  • ⚠️ Cannot be undone
  • ⚠️ Affects sales activity reports
  • ✅ Removes from customer visit history
⚠️ Important:
  • Check-ins track customer visits for sales performance
  • GPS coordinates verify location proximity
  • Distance measurement helps verify customer visits
  • Multiple check-ins allowed per customer per day
  • Check-in data feeds into sales activity dashboards
