📌 NUMBERING SEQUENCES

GET /api/settings/numbering-sequences

Retrieves document numbering sequences and prefixes configuration.

GET /api/settings/numbering-sequences

Sample Response

{ "status": true, "message": "Numbering sequences retrieved", "data": { "sales_invoices": { "prefix": "INV-", "suffix": "", "padding": 6, "separator": "-", "example": "INV-20251212-D72F5C" }, "purchase_orders": { "prefix": "PO-", "suffix": "", "padding": 6, "separator": "-", "example": "PO-20251212-ABC123" }, "orders": { "prefix": "ORD-", "suffix": "", "padding": 6, "separator": "-", "example": "ORD-20251212-XYZ789" }, "quotations": { "prefix": "QUOT-", "suffix": "", "padding": 6, "separator": "-", "example": "QUOT-20251212-DEF456" }, "deliveries": { "prefix": "DLV-", "suffix": "", "padding": 6, "separator": "-", "example": "DLV-20251212-GHI789" } } }
ℹ️ Number Format: {prefix}{date}{separator}{random}
• prefix: Document type identifier
• date: Current date (YYYYMMDD)
• separator: Dash or custom separator
• random: Random alphanumeric string

POST /api/settings/numbering-sequences

Updates document numbering sequences and prefixes.

Request Body

FieldTypeRequiredDescription
sales_invoices.prefixstringNoInvoice prefix
sales_invoices.paddingnumberNoRandom string length
sales_invoices.separatorstringNoSeparator character
purchase_orders.*variesNoPurchase order settings
orders.*variesNoOrder settings
quotations.*variesNoQuotation settings
deliveries.*variesNoDelivery settings
POST /api/settings/numbering-sequences { "sales_invoices": { "prefix": "INV-", "suffix": "", "padding": 6, "separator": "-" }, "purchase_orders": { "prefix": "PO-", "suffix": "", "padding": 6, "separator": "-" }, "orders": { "prefix": "ORD-", "padding": 6 } }
⚠️ Important: Changing numbering sequences will affect new documents only. Existing documents retain their original numbers.

📌 VALIDATION RULES

API Validation

Update Company Profile

{ "company_name": { "type": "string", "required": true, "minLength": 2, "maxLength": 255 }, "email": { "type": "email", "required": true }, "phone": { "type": "string", "optional": true, "pattern": "^[+0-9]{10,15}$" }, "currency": { "type": "string", "optional": true, "length": 3, "uppercase": true }, "logo_url": { "type": "url", "optional": true }, "website": { "type": "url", "optional": true }, "qr_code": { "type": "string", "optional": true } }

Update Layout Settings

{ "pos": { "type": "object", "optional": true, "properties": { "columns": { "type": "object" }, "gap": { "type": "number", "min": 0, "max": 12 }, "showImages": { "type": "boolean" }, "cardStyle": { "type": "enum", "values": ["standard", "compact", "detailed"] } } } }

Update Numbering Sequences

{ "sales_invoices": { "type": "object", "optional": true, "properties": { "prefix": { "type": "string", "maxLength": 10 }, "suffix": { "type": "string", "maxLength": 10 }, "padding": { "type": "number", "min": 4, "max": 10 }, "separator": { "type": "string", "maxLength": 5 } } }, "purchase_orders": { "type": "object", "optional": true }, "orders": { "type": "object", "optional": true } }
ℹ️ Common Validation Rules:
• Company name must be unique (single profile per system)
• Email must be valid format
• Currency code must be 3-letter ISO 4217 code (USD, EUR, GBP, etc.)
• URLs must be valid and accessible
• API keys are validated for format (not existence)
• Padding must be between 4-10 characters
📌 SIDE EFFECTS

Operations Impact

Updating Company Profile

  • ✓ Updates all future documents (invoices, quotes, orders)
  • ✓ Changes reflected in email templates
  • ✓ Logo and QR code updates affect printed documents
  • ✅ Currency changes affect all financial calculations
  • ✅ Does NOT modify existing documents (they retain original values)

Updating Layout Settings

  • ✓ Affects POS interface immediately
  • ✓ All users see updated layout on next refresh
  • ✅ Changes stored per user device in localStorage

Updating Numbering Sequences

  • ✓ Affects only NEW documents created after update
  • ✓ Existing documents keep their original numbers
  • ✅ Cannot be undone (sequences are not versioned)
  • ⚠️ Changing prefixes may cause confusion in document continuity

Updating API Keys

  • ✓ Changes take effect immediately
  • ⚠️ Invalid API keys will cause integration failures
  • ⚠️ Google Maps requires valid API key for map functionality
  • ⚠️ E-invoice API keys provide access to tax submission systems
⚠️ Important:
  • Settings changes are NOT versioned - backup before major changes
  • API keys should be rotated periodically for security
  • Test numbering sequences with sample documents before applying
  • Company profile changes affect all customer-facing documents
  • Keep API keys secure and never expose in client-side code
